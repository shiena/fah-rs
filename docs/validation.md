# 実機検証記録

2026年11月9日にSony SO-51Aで検証しました。
GPUはAdreno 650です。ドライバーのビルド日は2021年10月4日です。

## 検証対象

- FAH: `2b13dd9c7fc04ad173a76ab89beac9266d2d59ac`
- ncnn: `20261020`
- モデル: FAH-S、320×320、1手ずつ推論
- 実行方式: FP32、CPUは4スレッド、GPUはVulkan
- メッシュ・接触推定: 無効

最終測定値と各出力の差は[validation.json](validation.json)に保存しています。
元のログはローカルの`artifacts/`にあります。

| 計測対象 | 中央値 | 処理時間の逆数 |
|---|---:|---:|
| CPU・1手の姿勢モデル | 280.07 ms | 3.57 FPS |
| Vulkan・1手の姿勢モデル | 1,544.52 ms | 0.65 FPS |
| Vulkan・2手のサンプル処理全体 | 3,153.12 ms | 0.32 FPS |

姿勢モデルはウォームアップ2回の後に10回計測しました。
カメラ取得・描画時間は含みません。リアルタイム処理速度には達していません。

## 合格条件

2D座標の最大差を0.5ピクセル未満、3D座標の最大差を1mm未満としています。
座標の差は、同じ入力をPyTorchで処理した結果との比較です。
実データの正解座標に対する評価ではありません。

ランダム画像1件と実画像由来の4件を比較します。
実画像には左右反転と画像外の余白を含みます。
461点すべての2D・3D出力を比較します。
信頼度、可視性、深度、手の存在・左右の出力差も記録します。
Vulkanの5入力で観測した最大差は、2Dが約0.00256ピクセル、3Dが約0.000246mmでした。

## 動作確認

公開サンプルの2手を12回連続で処理しました。
12回とも2手を出力し、1回目と11回目に検出器を実行しました。
これは同じ静止画像を使った追跡状態と再検出周期の検査です。
動画の追跡精度ベンチマークではありません。

APKを端末へインストールし、カメラ画像の取得を確認しました。
実際の手から21関節を取得できることも確認しました。
サンプル画像に関節を重ねた結果は`artifacts/sample-result.png`にあります。

最終APKのCPUカメラ試験では約36秒間で76フレームを処理し、68フレームで手を出力しました。
この区間の推論エラーは0件でした。ネイティブ処理時間の中央値は376.51msです。
検出数は正解ラベルとの比較ではなく、動作確認の記録です。
カメラから保存した1手の静止画像も、Vulkanで12回連続処理し、CPUへの切り替えなしで通過しました。
集計は[camera-validation.json](camera-validation.json)に保存しています。

最終版のVulkanカメラ試験では約49秒間で46フレームを処理しました。
推論エラーとCPUへの切り替えは0件でしたが、手の出力は1フレームだけでした。
この試験だけで、動く手をVulkanで連続追跡する安定性を確認したとは判断していません。
検証後は、端末でCPUモードのカメラ画面を起動しています。

## GPU実装上の制約

ncnn標準の集約演算は、この端末で基準値との差が大きくなりました。
専用のVulkan集約シェーダーに置き換えています。
GELUはPyTorchのerf方式に合わせています。
LayerNormも平均・分散をFP32で計算する専用シェーダーを使います。
Attentionの行列積は、CPUへの切り替えを避けるため専用シェーダーで実行します。

姿勢モデルの713ノードは、すべてVulkan対応として読み込まれます。
ただし、ドライバーの安定性を確保するため、各エンコーダーブロックの終了時にCPUへ結果を読み戻します。
したがって、Metal版の単一コマンドバッファー構成や転送量を再現していません。

カメラ表示との同時実行ではGPUのDevice Lostエラーを観測しました。
Vulkan使用時は推論中のプレビューを停止します。
CPU使用時はプレビューを継続します。

開発中のカメラ試験では、GPU出力に不正値が出るケースも観測しました。
最終版はGPU推論エラー時にCPUで再試行し、以後の処理をCPUへ切り替えます。
画面と結果JSONで切り替えを明示します。切り替えに要した時間は`recovery_ms`と`total_ms`に含めます。
この回復処理を含め、あらゆるGPUドライバー障害から復帰できることは検証していません。

FP16経路は精度検査に不合格でした。
アプリではFP32のみを使用します。
他機種での互換性、長時間の発熱、バッテリー消費は未評価です。
